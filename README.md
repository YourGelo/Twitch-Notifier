# Twitch Notifier

Простой Python-бот: проверяет один канал Twitch, отправляет Telegram-уведомление
о начале эфира и удаляет его после завершения. Состояние сохраняется в JSON между
перезапусками. Это небольшая portfolio-версия с одним циклом обработки.

```text
Twitch API → live / offline → Telegram sendMessage / deleteMessage
                           ↕
                       data/state.json
```

## Запуск

Нужны Python 3.12 или Docker Compose, приложение Twitch с Client ID и Client Secret,
Telegram-бот и чат, где бот может отправлять и удалять свои сообщения.
Получите собственные значения в консолях соответствующих сервисов.

```sh
cp .env.example .env
# Заполните все replace-... в .env
docker compose up --build -d
docker compose logs -f bot
docker compose down
```

PowerShell: `Copy-Item .env.example .env`. `TWITCH_LOGIN` — логин без URL;
`TELEGRAM_CHAT_ID` — ID чата или имя канала вида `@channel`.
Состояние хранится в volume `state`. Порты не публикуются.
`docker compose down -v` удаляет состояние: не используйте эту команду во время
эфира, иначе бот забудет ID уже отправленного сообщения.

Без Docker:

```sh
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m bot.main
```

`POLL_SECONDS` — интервал проверки (60 по умолчанию, минимум 10).
`STATE_PATH` — путь к файлу состояния (по умолчанию `data/state.json`).
Запускайте только один экземпляр с одним файлом состояния.

## Как работает код

- `bot/clients.py` — HTTP-запросы к Twitch и Telegram. Twitch app token кэшируется
  и обновляется при истечении срока или одном ответе 401. Секрет передаётся в теле
  запроса. URL Telegram с токеном не выводится в логи.
- `bot/main.py` — polling. Тот же stream ID не создаёт повторное сообщение.
  Ответ Twitch с пустым `data` означает offline; сетевая ошибка — нет.
  Новый stream ID завершает предыдущее уведомление, даже если offline пропущен.
- `bot/state.py` — сохранение через временный файл и замену. Вместе с ID сообщения
  сохраняется чат; неуспешное удаление повторяется на следующей успешной проверке.
  Повреждённый файл состояния останавливает процесс.

Текст сообщения простой, без HTML-разметки и дополнительных шаблонов.
Задержка обнаружения начала и конца эфира зависит от интервала опроса.

## Тесты

```sh
pip install -r requirements-dev.txt
ruff check .
ruff format --check .
pytest -q
```

Тесты не отправляют настоящих сообщений: проверяют live/offline, сохранение
состояния, отсутствие повтора, смену stream ID, сбои Twitch, retry удаления,
обновление токена и обработку HTTP-ошибок через MockTransport.
GitHub Actions запускает тесты, линтер и проверку Compose.

## Ограничения

Это один канал, один бот, один процесс. Нет панели управления или распределённых
блокировок. Если процесс завершится между успешной отправкой Telegram и сохранением
ID, следующий запуск может отправить дубль. Такая же неопределённость возможна
при таймауте отправки: Telegram не предоставляет ключ идемпотентности для sendMessage.

Один успешный ответ offline завершает уведомление. Telegram ограничивает удаление
старых сообщений и может отказать из-за прав; такие удаления остаются в очереди
повтора и требуют проверки прав или ручного удаления. Сначала остановите бот перед
ручным изменением состояния. Реальную доставку проверьте со своим тестовым чатом:
начните эфир, дождитесь сообщения, перезапустите бот (дубля быть не должно),
завершите эфир и дождитесь удаления.
